## Варіант 2: Список справ

### Інструкція запуску
* Відкрити проект.
* Перейти з No Device на Start Medium Phone API 35 mobile emulator (cold boot).
* Створити новий термінал.
* Ввести команду futter run.

## Таблиця стану

| Які дані (що саме зберігається) | Де живуть (у якому віджеті / класі) | Чому саме там (аргументація вибору) |
| :--- | :--- | :--- |
| **Ефемерний стан:**<br>• Текст у полях введення (`TextEditingController`)<br>• Тимчасові помилки валідації полів | Усередині локальних `StatefulWidget` (`TodoInputWidget`, `EditTodoScreen`) через `setState` | Стосується виключно процесу введення тексту в одному конкретному віджеті. Немає сенсу піднімати ці дані вище, оскільки вони не цікаві іншим частинам додатку. |
| **Ефемерний стан:**<br>• Обраний фільтр списку (`TodoFilter.all / active / completed`) | У локальному стейті екрана (`HomeScreen` через `setState`) | Фільтрація списку виконується в межах головного екрана. Зміна фільтра не змінює саму модель даних у базі/пам'яті, а лише сортує поточне відображення для користувача. |
| **Спільний стан програми:**<br>• Перелік усіх справ (`List<Todo>`)<br>• Бізнес-логіка (`add`, `toggle`, `update`, `remove`, `restore`) | У класі `TodoModel` (`ChangeNotifier`), який надається через `InheritedNotifier` (`TodoScope`) | Це глобальні дані програми, до яких мають доступ кілька різних екранів та віджетів (Головний екран, Список, Лічильник в AppBar, Екран редагування). Використання `InheritedNotifier` дозволяє уникнути зайвого прокидування колбеків через конструктори та забезпечує точкові перебудови. |
